# Loco

Loco is a location-based daily offers site. Customers browse public promotions. Business owners publish offers for their own branches. Super admins manage the platform. Billing is not enabled.

## Design preview

Leave `MONGODB_URI` empty in development. The public site, owner dashboard, and super admin dashboard then render the sample records in `src/data/preview.json`. A yellow bar marks those screens. Dates stay relative to today, so current offers remain visible. Saving, publishing, and uploads wait until a database is connected. Set `MONGODB_URI` and the same screens switch to live data. The sample file is not used in production.

## Setup

1. Copy `.env.example` to `.env.local`.
2. Create a MongoDB Atlas database whose name contains `dev`, `test`, or `local`, and set `MONGODB_URI`.
3. Set `AUTH_SECRET` to a random string of at least 32 characters.
4. Install and start the app:

```bash
npm install
npm run dev
```

The first database connection creates the Mongoose indexes, including the `2dsphere` indexes on branch and offer locations.

## Accounts

Customers register at `/register`. Owners register at `/owner/register`. Super admin accounts are not created from either form.

Create the first super admin from the shell:

```bash
SEED_ADMIN_EMAIL=you@example.com SEED_ADMIN_PASSWORD="A-long-password-1" SEED_ADMIN_NAME="Platform admin" npm run create-admin
```

On Windows PowerShell, set the variables first:

```powershell
$env:SEED_ADMIN_EMAIL="you@example.com"
$env:SEED_ADMIN_PASSWORD="A-long-password-1"
npm run create-admin
```

Sign in at `/super-admin/login`. The script refuses to turn an existing customer or owner into a super admin.

`npm run seed` loads sample businesses in Bengaluru, Mumbai, and Hyderabad, plus development accounts. It refuses to run when `NODE_ENV=production` unless `SEED_CONFIRM=yes`. `SEED_RESET=yes` deletes this application's collections first, and only when the database name looks like a development database or `SEED_CONFIRM=yes`. The script prints the development passwords when it finishes. Do not reuse those passwords outside a local database.

## Images and email

Development stores approved JPEG, PNG, and WebP uploads in `public/uploads`. Production uploads require `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET`. Without them, the upload API returns a storage error.

Password reset email is sent when `SMTP_HOST` and `EMAIL_FROM` are set. Otherwise, development prints the reset URL in the server console and production records that email is not configured. The API response never says whether the address exists.

## Search and SEO

Nearby search uses MongoDB `$geoNear`. The radius is capped by `MAX_SEARCH_RADIUS_KM` and never exceeds 100 km. Customer coordinates stay in browser session storage. They are not added to public URLs, titles, or activity logs.

`/sitemap.xml` and `/robots.txt` are generated by the app. Set `GOOGLE_SITE_VERIFICATION` to the Search Console token. Private dashboards, account pages, login pages, and `/search` are disallowed. City and category pages are indexed only when they have current offers.

## Deployment

Deploy the Next.js app to Vercel and keep MongoDB on Atlas. Set the same environment variables in the Vercel project. `APP_URL` should be the production origin, with no trailing slash. Run `npm run create-admin` against the production database once, from a trusted machine, to provision the first super admin. Do not run the sample seed against production.

## What is not implemented

- Subscription plans, payments, and revenue. Those pages stay empty on purpose and do not show sample money.
- A map geocoder. Branch coordinates come from the browser geolocation button or from values the owner types.
- Continuous location tracking.
- Redis. Login, search, and report limits are stored in MongoDB.
- Production image uploads without Cloudinary.
- Password reset email without SMTP.

`npm test` covers dates, offer validity, search limits, role redirects, and validation. `npm run build` compiles without a database connection.
